# 玩法机制：从视觉关系到可重制体验

每次首次编译在槽位设计前读取；返修涉及玩法、目标关系或身份特征权限时重新执行。这里规定语义判断的完成标准，证据写入现有分析字段，不扩展正式 JSON 或分析 Schema。

## 先观察关系，再确定控制

查看图片，先写一句能区分这张图与同题材普通图片的机制描述。使用“谁的什么部位，以什么方式，与什么相连或发生变化”等具体表达。吸引力也可以来自表情反差、动作关系、文字包袱、比例、布局或媒介组合；按图取证，普通肖像无需虚构额外隐喻。

沿着视觉焦点检查相邻部位的边界、轮廓走势、材质过渡、遮挡与接触，判断它们是背景衬托、穿戴附着、内容容纳，还是形态融合、替代或连续生长。只检查有画面根据的关系，不要求每张图覆盖全部类型。

- 用具体位置和可见细节支持判断，例如“头顶发束的外轮廓延续为向上卷曲的火舌，内外色层连续”。共同颜色或位置接近只能作为辅助证据。
- 同时存在两种合理解释时，写明各自依据，回看交界处判定。确实看不清时，记录不确定范围；会改变核心玩法或绑定的不确定项解决前暂缓该项编译。
- 在 `visualMechanism` 与 `templateValue.fixedMechanism` 写下选定关系，在 `playDecisionModel.funProposition/userRecreationWish` 说明它为何值得用户重制。随后在 `componentGraph/spatialRelations` 中记录对应部位和关系。

## 反事实：什么一变就丢了玩法

在选槽前完成两种纸面代入，将结论连同图像依据写入 `templateValue.whySelected/templateHook` 的现有文本：

1. **关系消融**：保留物体和画风，把候选核心关系移除或改成普通并置。指出具体失去的视觉效果或包袱。若体验基本不变，重新判断它是否只是装饰。
2. **身份替换**：换成外观明显不同的合法主体或内容。指出哪些特征随输入改变，哪些关系必须继续成立，以及交界处如何适配。单说“保持原风格”不足以说明玩法成立。

核心关系、画法和开放内容由此分别确定。将可变身份、颜色或物件替换后仍成立的体验写进标题和描述，避免用“华丽、酷炫”等情绪词代替机制。

## 联动范围与特征权限

对每个候选控制追踪“改变输入 → 直接改变部位 → 为保持关系必须共同变化的部位”，在对应 `slotEvidence` 的现有理由、binding 决议及 `featureAuthority` 中记录。

- 一个配色控制可能作用于融合造型的多个区域。列全受控范围，并用合同允许的内容目标和 binding 表达；身份 binding 继续控制身份。关系约束说明交界处如何连续，以及内容控制覆盖身份外观的具体范围。普通受光变化单独说明，不自动重着色整个主体。
- 形态融合可作为一个视觉内容目标覆盖连续区域；多个可寻址区域也可按现有分配策略绑定。以真实可执行范围选择，不因分析拆了组件就强行拆槽。
- 身份特征权限遵守最小例外。若头发火焰化承载玩法，`hair` 可用 `template/explicit_transformation`，在 `evidence` 说明需变换的材质、延展形态及仍可保留的身份线索；身份本身继续归 `source`。现有枚举仅支持 source/template，不新增 hybrid 等值，也不同时将同一特征列为完整继承与完整固定。
- 所有相关内容都开放时，检查不同输入组合能否共同成立。需要后端尚未支持的同步或映射时明确记录限制，前台文案不承诺自动联动。

将机制投影到前台与后端：Prompt 用自然语言让用户理解玩法，例如“主角的头发化作升腾的火焰”；`visualContract.relations` 描述连接起点、延伸方向和遮挡，画法及色彩字段描述连续处理。target 的 role/region 同样与该关系一致。

## 最终草稿复核

重看图片，再对照最终字段；已有 `selfReview` 检查项按下表提供证据，保持检查键全集不变。

| 检查项 | 本轮必须回答 |
| --- | --- |
| `playHypothesisGrounded` | 哪个可见关系支撑玩法？关系消融会失去什么？ |
| `slotPrecisionComplete` | 每项控制影响哪些部位？联动区域是否完整？ |
| `featureAuthorityComplete` | 身份保真与模板变形的边界是什么？是否存在会抵消玩法的继承要求？ |
| `visualContractRespectsInputs` | 代入不同推荐项后，Prompt、target、binding 和视觉合同是否共同保留该关系？ |

至少检查一个明显不同的身份或内容值；存在联动配色时再检查换色后的连接区域。记录具体字段和结论，发现矛盾后重建草稿与 SHA。基础 Schema 通过仅证明结构有效；本步骤是 Agent 的语义复核，真实生成效果仍需另行验证。不以耗时或文字长度作为完成标准。
